# RustNT 总体路线图

**更新时间：** 2026-09-19

RustNT 的目标是用 Rust 构建一组清晰、可测量、受控的 Windows 用户态能力，
逐步替换部分 Windows Shell 体验，同时保留 Windows 内核、驱动、DWM、Win32
兼容层和现有安全模型。

RustNT 不会把所有界面程序运行成 SYSTEM，也不会通过 PowerShell、任意脚本或
任意命令执行来获得“高权限”。需要高权限的操作统一经过固定能力、审计和
授权检查的 LocalSystem 服务。

## 阶段一：系统基础

| Task | 内容 | 状态 |
| --- | --- | --- |
| 01 | Cargo Workspace、Win32 进程枚举、PID、线程、内存 | 已完成 |
| 02 | 进程路径、CPU、过滤、排序、Watch 模式 | 已完成 |
| 03 | LocalSystem 服务桥接、SCM、身份和权限边界 | 已完成 |
| 04 | Named Pipe 固定协议、ACK、超时、断线和停止处理 | 已完成 |
| 05 | `rustnt-service.exe` 服务宿主和生命周期 | 已完成 |
| 06 | 服务安装、启动、停止、状态和身份 CLI | 已完成 |
| 07 | 架构文档、学习笔记、基准和验证规范 | 已完成 |
| 08 | 受控进程查看和终止、PID 复用与 SID 所有权校验 | 已完成 |

Task08 的代码验证已经完成，但真实 Administrator/UAC 环境下的服务启动、
临时进程终止和清理仍由 Task09 完成。

## 阶段二：安全与系统能力

| Task | 内容 | 主要产物 |
| --- | --- | --- |
| 09 | Task08 提权端到端验证和安全收尾 | 测试矩阵、审计记录、清理验证 |
| 10 | 能力授权与审计框架 | 固定 capability、请求 ID、操作日志、限流 |
| 11 | 系统监控 v1 | CPU、内存、磁盘、进程变化等只读监控 |
| 12 | 文件系统只读能力 | 文件、目录、磁盘空间、权限和搜索 |
| 13 | 窗口和会话查看器 | 窗口、桌面、会话、前台窗口和进程关系 |

这一阶段优先做只读能力和安全边界，不做任意命令执行、批量终止、驱动安装
或未审计的系统修改。

## 阶段三：RustNT Shell

| Task | 内容 | 主要产物 |
| --- | --- | --- |
| 14 | GUI 基础框架 | Rust GUI、事件循环、主题、配置和崩溃恢复 |
| 15 | 桌面交互组件 | 启动器、任务切换器、快捷键、状态栏和通知入口 |
| 16 | 文件管理器 v1 | Rust 文件浏览和常用文件操作 |
| 17 | Shell 集成与恢复机制 | 手动切换、回退、崩溃恢复和安全退出 |
| 18 | 窗口管理和工作区 | 窗口布局、工作区和虚拟桌面辅助能力 |

初期继续使用 Windows DWM 和 Win32 窗口系统，不自己实现显示驱动或完整
合成器。RustNT 首先替换用户体验层，而不是替换 Windows 图形内核。

## 阶段四：性能和底层研究

| Task | 内容 | 进入条件 |
| --- | --- | --- |
| 19 | 完整性能基线和回归测试 | 已有可重复的功能实现 |
| 20 | 受控 Native NT API 优化 | Win32 确认成为实际瓶颈 |
| 21 | 系统级插件和扩展模型 | capability 和审计框架稳定 |
| 22 | 生产部署、升级和回滚 | Shell 和服务功能稳定 |
| 23 | 可选驱动/内核边界研究 | 用户态确实无法满足需求，并在虚拟机中验证 |

Task23 是最后的可选方向。即使执行，也只增加受签名和回滚约束的驱动边界，
不会替换 Windows NT 内核或现有驱动体系。

## 每个 Task 的执行流程

1. 调查现有代码和 Windows API 边界。
2. 编写并确认设计规格。
3. 编写实现计划。
4. 先写失败测试，再实现最小行为。
5. 运行定向测试、工作区测试、构建、Clippy 和格式检查。
6. 做只读代码审查和必要的审查修正。
7. 更新文档、验证报告和进度记录。
8. 使用独立提交保存可回滚的结果。

## 当前下一步

Task09 先完成 Task08 的真实提权验证和安全收尾。只有 Task09 的服务启动、
授权拒绝、正常终止、PID 复用和清理流程稳定后，才进入 Task10 的能力授权
框架和后续监控、文件系统、Shell 工作。
