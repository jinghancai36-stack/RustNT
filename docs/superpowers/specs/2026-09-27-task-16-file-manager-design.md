# Task16 文件管理器 v1 设计规格

**日期：** 2026-09-27
**状态：** 已确认范围，待实现计划

## 目标

在 RustNT 单窗口 GUI 中加入一个安全的只读文件管理器页面，用于浏览
Windows 文件系统目录和查看基础元数据。Task16 不执行任何文件写入或外部
程序调用，继续保持 RustNT 为 Windows 用户态应用。

## 范围

### 包含

- 将 Task15 中未连接数据源的 `Windows & Sessions` GUI 占位页替换为
  `File Manager` 页面；Task13 的窗口与会话能力仍保留在 core 和 CLI 中。
- 以当前用户目录作为首选初始目录；环境变量不可用或目录无法读取时，退回
  到当前进程目录，并将读取错误显示在页面内。
- 读取并展示当前目录的直接子项，不递归加载目录内容。
- 显示名称、类型、大小、最后修改时间和重解析点标记。
- 进入子目录、返回上级目录、后退、前进和刷新。
- 显示当前路径和稳定的目录状态信息。
- 按名称、类型、大小、修改时间排序，并支持升序或降序。
- 按名称进行大小写不敏感的包含过滤；过滤只作用于当前已加载目录。
- 将访问拒绝、路径不存在、路径类型错误和其他文件系统错误转换为页面内
  的可读错误状态。

### 不包含

- 不打开文件，不调用系统默认程序，不启动外部进程。
- 不创建、删除、复制、移动、重命名或修改文件和目录。
- 不递归搜索、不计算目录总大小、不读取文件内容。
- 不添加全局热键、Shell 注册、资源管理器扩展、服务、Named Pipe、驱动、
  内核接口或新的特权能力。
- 不向配置文件持久化浏览历史、过滤器或选中项。

## 用户界面

文件管理器使用现有 Task15 单窗口 Shell 和 egui 主题：

- 顶部工具区显示后退、前进、上级目录、刷新按钮、路径输入框和当前状态。
- 路径输入提交后尝试加载目标目录；失败时保留当前有效目录并显示错误。
- 主区域使用稳定列布局展示条目。目录显示目录标识，文件显示文件标识，
  重解析点显示额外状态，不使用图标或文本伪造权限状态。
- 单击目录行选中它；双击目录进入该目录。文件不产生打开行为。
- 工具区提供名称过滤、排序字段和排序方向控件。
- 空目录显示明确的空状态；加载失败显示错误和重试入口。
- 所有按钮只作用于 RustNT 当前窗口，继续使用现有本地快捷键体系。

## 架构

### Core 数据适配

GUI 增加对现有 `rustnt-core` workspace crate 的路径依赖，调用
`rustnt_core::filesystem::list_directory` 获取直接子项，并使用已有的
`DirectoryEntry`、`FileMetadata` 和 `FileKind` 类型。Task16 不修改服务协议、
授权模型或 filesystem Win32 资源管理实现。

### 浏览状态

新增聚焦于状态转换的 `file_browser.rs`，负责：

- 当前有效路径、后退栈、前进栈和当前目录条目。
- 过滤文本、排序字段、排序方向和选中路径。
- 进入目录时清理前进栈；后退或前进时更新路径并重新加载。
- 计算安全的父目录，不能从盘符根目录或 UNC 共享根目录继续向上。
- 将加载成功、空目录和失败分别表示为可测试的状态。

文件系统读取通过一个可注入的加载函数进入状态模型，使路径历史、排序、
过滤和错误恢复测试不依赖真实窗口。生产路径使用 `list_directory`；测试
使用固定内存条目。

### GUI 集成

`app.rs` 继续负责 Shell 布局、主题、通知和配置恢复；文件管理器页面的
状态和纯逻辑放在 `file_browser.rs`。导航元数据把第三个页面改名为
`File Manager`，Ctrl+3 保持本地页面切换行为不变。文件管理器加载失败时
通过现有通知中心加入一条错误通知，但每次刷新只产生一条通知，不能在每帧
渲染中重复产生。

## 错误处理与安全边界

- 所有路径读取使用既有 `rustnt-core` 错误类型，错误不会触发 panic。
- 输入路径在 core 层继续经过现有规范化和 NUL 校验。
- 页面只保留最近一次加载错误，成功加载后清除旧错误。
- 目录读取失败不会覆盖当前有效条目；用户可以修改路径或点击刷新重试。
- 不为了读取文件而申请写权限，不绕过 ACL，不提升进程权限。

## 测试策略

- 浏览模型：初始状态、进入目录、父目录边界、后退/前进栈、失败保留当前
  目录、成功后清除错误。
- 视图模型：目录优先排序、名称/类型/大小/时间排序、升降序切换、大小写
  不敏感过滤、空目录状态和重解析点标记。
- GUI：File Manager 页面路由、路径提交、刷新/导航按钮、错误状态和通知
  只触发一次；不依赖 native window。
- 回归：Task14 配置和恢复测试、Task15 导航与通知测试全部保持通过。
- 验证命令包括 GUI 定向测试、workspace check/build/Clippy/format、全量
  workspace 测试和 `git diff --check`。

## 验收标准

1. GUI 第三个页面显示为 File Manager，并且不再显示未连接数据源占位文案。
2. 用户可以在当前窗口内浏览目录、返回、前进、刷新和输入路径。
3. 用户可以稳定地过滤和排序当前目录的直接子项。
4. 访问错误可见且不会清空最后一次有效目录内容。
5. Task16 不执行任何文件或目录写操作，不启动外部程序，不增加特权能力。
6. 所有新增逻辑有单元测试，Task14/Task15 既有测试和 workspace 验证全部通过。
