# Task17B 手动 Shell 切换设计规格

**日期：** 2026-10-08  
**状态：** 设计已确认，待实现计划  
**范围：** Task17B；采用一次性管理员辅助程序、独立 Shell 启动引导器和 Explorer 回退

## 1. 目标

Task17B 为 RustNT 增加可选、手动、可回滚的 Windows Shell 切换能力。用户明确发起
切换并通过 UAC 后，RustNT 可以将当前用户后续登录时的 Windows Shell 指向 RustNT
启动引导器；引导器负责启动 RustNT GUI，并在 RustNT 无法启动时回退到 Explorer。

本 Task 的目标不是替换 Windows 内核、DWM、Win32 窗口系统或 Windows 登录认证，
而是在保留 Windows 图形和安全基础设施的前提下，提供一个可以随时恢复的用户体验层
实验能力。

## 2. 明确不包含

Task17B 不包含以下行为：

- 不自动启用 Shell 切换；安装、更新和普通启动均不修改 Winlogon；
- 不直接让普通权限 GUI 写入 HKLM；
- 不向长期运行的 LocalSystem 服务增加注册表写入能力；
- 不修改驱动、内核、DWM、服务授权、Named Pipe 协议或现有进程终止策略；
- 不接受任意可执行路径、命令行、脚本、PowerShell、WMI、`reg.exe` 或任意外部命令；
- 不修改除固定 Winlogon 键值之外的启动项、策略、Userinit 以外的登录配置或安全设置；
- 不在当前开发机上默认执行真实 Shell 切换；真实切换只能在专用虚拟机验收；
- 不把“启动成功”推断为“注册表写入成功”，每次写入都必须读取验证；
- 不覆盖不是由当前 RustNT 事务写入的外部配置。

## 3. 推荐架构

### 3.1 组件

Task17B 使用三个职责隔离的组件：

1. **RustNT GUI**：普通用户权限运行，只显示当前状态并发起固定操作请求：
   `prepare_switch`、`switch`、`restore` 和 `show_recovery`。GUI 不接收注册表路径、
   值名或任意命令参数。
2. **一次性管理员辅助程序**：固定安装路径下的 `rustnt-shell-helper.exe`，通过 UAC
   以管理员权限运行，执行一次事务后退出。它只允许读写固定的 Winlogon 键值，并且
   只使用内置的 RustNT 引导器路径和当前安装清单。
3. **Shell 启动引导器**：固定安装路径下的 `rustnt-shell-bootstrap.exe`，作为
   Winlogon `Shell` 的目标。它不依赖 eframe 或完整 GUI 状态，负责启动 RustNT GUI，
   监视启动结果，并在失败、超时或 GUI 立即退出时启动固定的 `explorer.exe` 回退。

一次性辅助程序采用管理员权限而不是 LocalSystem。现有 LocalSystem 服务继续只承担
已有的固定服务能力，避免把系统配置写入能力加入长期运行的 SYSTEM 边界。

### 3.2 固定的系统目标

只允许访问：

- 注册表键：`HKLM\\SOFTWARE\\Microsoft\\Windows NT\\CurrentVersion\\Winlogon`；
- 值：`Shell` 和 `Userinit`；
- Shell 切换时实际修改：仅 `Shell`；
- `Userinit`：读取并备份，但保持原值不变；恢复时仅在事务证明该值由 RustNT 改动时才允许写回；
- 回退程序：系统目录中的 `explorer.exe`，路径由 Windows 系统目录 API 解析，禁止用户输入；
- RustNT 目标：由安装清单解析并验证的固定 `rustnt-shell-bootstrap.exe` 与
  `rustnt-gui.exe`，禁止从 GUI 请求中传入路径。

注册表值必须是预期的 `REG_SZ` 类型。未知类型、缺失值、嵌入 NUL、超出长度限制、
无法规范化路径或安装清单不匹配时，辅助程序拒绝切换。

## 4. 切换事务

### 4.1 事务状态

事务使用版本化 TOML 文件，状态只能按以下顺序推进：

`Prepared` -> `BackedUp` -> `ShellWritten` -> `ReadBackVerified` -> `Committed`

失败状态为 `Failed`，恢复状态为 `RestoreRequested` -> `Restored`。每个事务包含：

- 格式版本；
- 唯一 nonce；
- 创建时间和发起进程标识；
- 原始 `Shell` / `Userinit` 的类型、长度和摘要；
- RustNT 预期写入值的长度和摘要；
- 写入前后验证结果；
- 固定事件名和受限错误类别。

事务文件不得保存完整的 Winlogon 字符串到普通用户可读位置。备份内容保存于
`%ProgramData%\\RustNT\\ShellSwitch`，目录由安装或管理员辅助程序创建，并限制为
SYSTEM、Administrators 和 RustNT 管理边界可访问。`%APPDATA%\\RustNT` 继续只保存
GUI 状态、Task17A 快照和恢复提示，不承担系统级备份职责。

### 4.2 切换流程

1. GUI 展示当前只读快照、风险说明和恢复方式，要求用户明确点击切换。
2. GUI 请求固定的 `switch` 操作，辅助程序通过 UAC 启动。
3. 辅助程序获取跨进程事务锁，读取并验证当前 `Shell` / `Userinit`。
4. 辅助程序将原始元数据和受保护备份写入临时文件，原子替换备份文件，并重新读取确认。
5. 辅助程序将事务推进到 `BackedUp`，随后只写入固定的 RustNT 引导器目标。
6. 辅助程序读取 `Shell` 并验证类型、规范化目标路径和预期摘要。
7. 验证成功后推进到 `Committed`，释放事务锁并退出；验证失败则只在当前值仍等于
   RustNT 预期值时执行恢复，不能覆盖外部并发修改。
8. 辅助程序退出后，当前 Explorer 不被强制终止；切换在下一次 Windows 登录会话生效。

### 4.3 恢复流程

1. GUI 或独立恢复入口请求固定的 `restore` 操作并通过 UAC 启动辅助程序。
2. 辅助程序验证事务、备份完整性、nonce 和当前 `Shell` 是否仍是 RustNT 写入的目标。
3. 当前值不匹配时拒绝自动恢复并报告“外部修改”，防止覆盖管理员或系统更新的配置。
4. 当前值匹配时恢复原始 `Shell`，并按备份状态处理 `Userinit`；未由 RustNT 修改的
   `Userinit` 不写回。
5. 读取验证成功后，事务推进到 `Restored`，保留审计结果，不删除最后一份有效备份。

恢复入口必须独立于完整 RustNT GUI：启动引导器在 GUI 启动失败时提供有限的恢复提示，
并可调用固定的管理员辅助程序；管理员也可以从任务管理器运行固定的
`rustnt-shell-helper.exe --restore`。该参数只表示固定操作，不接受路径或脚本。

## 5. 启动引导器与 Explorer 回退

引导器是最小的 Windows GUI/Win32 进程，不加载完整 Shell 页面、文件浏览器或服务客户端。
它按以下顺序工作：

1. 验证自身路径、安装清单和 Task17B 事务状态；
2. 启动固定路径的 `rustnt-gui.exe`，使用受限的启动参数；
3. 在固定超时内等待 GUI 报告已进入可用状态；
4. GUI 启动成功后继续等待 GUI 退出；
5. GUI 启动失败、崩溃、超时或事务状态不可恢复时，启动系统目录中的
   `explorer.exe`，记录固定的回退原因并退出。

引导器不修改注册表、不执行任意命令、不解释用户提供的命令行，不依赖 PowerShell，
也不因为 GUI 退出而强制终止其他进程。Explorer 回退只允许启动一次，避免失败循环。

## 6. 错误与安全策略

- 辅助程序无法获取事务锁时拒绝操作，不等待无限时间；
- 备份写入、原子替换、注册表写入或读取验证失败时，事务进入 `Failed`；
- 写入后发生进程崩溃时，下一次引导器启动必须优先使用事务状态和备份验证，不能盲目继续切换；
- 恢复时发现当前值不是 RustNT 预期值，必须拒绝覆盖并显示人工处理要求；
- 所有日志只写固定事件、摘要、状态和 Win32 错误码，不写完整 Shell/Userinit 字符串；
- 事务、备份和日志都有格式版本、大小限制、临时文件清理和损坏文件保留策略；
- 管理员辅助程序拒绝从普通用户可写目录加载自身、引导器或安装清单；
- 更新或卸载前必须先恢复 Explorer，否则操作失败并保留现有 Shell 配置；
- 默认关闭切换功能；没有有效备份、可验证回退程序和可用恢复入口时，禁止写入 HKLM。

## 7. 测试策略

### 7.1 注入式单元测试

使用注册表适配器和进程启动适配器，不触碰真实 HKLM：

- 固定路径和固定值名校验；
- 未知注册表类型、NUL、超长值、路径不匹配拒绝；
- 备份原子写入和损坏备份保留；
- 正常切换状态顺序；
- 写入失败、读取验证失败、辅助程序中止后的恢复；
- 外部修改检测后拒绝覆盖；
- nonce 防止旧事务恢复新事务；
- 引导器 GUI 启动失败、超时、立即退出时只回退一次 Explorer；
- 禁止任意命令、路径和额外参数进入进程启动适配器；
- Task17A 既有启动事务和快照测试继续通过。

### 7.2 虚拟机验收

真实 Winlogon 写入只允许在可快照回滚的 Windows 虚拟机执行，验收矩阵包括：

1. Explorer 默认状态下 RustNT 不改变系统配置；
2. 明确 UAC 确认后切换，注销并重新登录进入 RustNT；
3. RustNT GUI 被阻止或损坏时自动进入 Explorer；
4. 从 GUI 和任务管理器恢复 Explorer；
5. 中断写入、重启、更新失败和恢复失败均能进入 Windows 桌面；
6. 恢复后 Winlogon 值与切换前的原始值一致；
7. 卸载或升级在未恢复时被拒绝。

当前开发机不执行上述真实切换验收，也不在普通开发迭代中写入 HKLM。

## 8. 实现边界与交付物

实现阶段预计新增独立模块或二进制，职责不得混入现有 GUI 页面：

- `rustnt-shell-helper`：管理员事务、固定 Winlogon 访问、备份和恢复；
- `rustnt-shell-bootstrap`：启动 RustNT、等待健康状态和 Explorer 回退；
- GUI 集成：只发起固定操作、显示状态和恢复提示；
- Task17A 模块扩展：复用版本、nonce、事务锁和有界日志原则，不改变现有语义；
- 文档：安装前置条件、虚拟机验收步骤、人工恢复步骤和明确的安全限制。

实现完成的最低验收条件是：所有离线测试通过、工作区构建和 Clippy 通过、注册表与
进程边界扫描通过、当前开发机没有真实 Winlogon 写入，并且虚拟机验收矩阵中的回退和
恢复证据齐全后才允许考虑默认启用。
