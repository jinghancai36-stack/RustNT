# Task17A Shell 快照与恢复机制基础设计规格

**日期：** 2026-09-30  
**状态：** 已确认设计，待实现计划  
**范围：** Task17A；不包含实际 Shell 切换

## 1. 目标

Task17A 为后续可选的 Shell 集成建立只读、可审计、可恢复的基础能力：

- 读取当前用户的 Windows Shell 配置并生成版本化快照；
- 记录 RustNT 启动事务、正常退出、异常退出和恢复事件；
- 将快照和日志限制在 `%APPDATA%\\RustNT` 应用数据目录；
- 在快照或日志不可用时允许 GUI 继续启动；
- 为未来 Task17B 的手动 Shell 切换提供状态和恢复证据，但不执行切换。

## 2. 明确不包含

Task17A 不执行下列行为：

- 不写入、删除或修改 Windows 注册表；
- 不修改 `Shell`、`Userinit`、启动项、策略或其他系统配置；
- 不启动、停止、重启或控制 Explorer 或其他外部进程；
- 不调用 PowerShell、`reg.exe`、WMI 或任意外部命令；
- 不申请管理员权限，不改变服务、Named Pipe、驱动、内核或授权边界；
- 不把快照文件作为切换授权，不自动恢复或替换 Windows Shell；
- 不记录密码、访问令牌、完整环境变量或未经限制的注册表值内容。

## 3. 与现有 GUI 的集成

Task14 已提供 `ConfigPaths`、运行标记、崩溃日志和异常启动恢复。Task17A
在这些能力旁边增加独立模块，不改变现有运行标记和配置文件语义：

- `shell_snapshot.rs`：只读注册表适配器、快照模型和快照保存；
- `shell_recovery.rs`：启动事务、状态转换和恢复事件日志；
- `config.rs`：扩展 `ConfigPaths`，只增加 Task17A 文件路径，不改变已有路径；
- `main.rs`：在 GUI 启动和正常退出边界调用协调器；
- `lib.rs` 或模块声明：按现有 GUI crate 结构暴露新模块。

现有 `recovery.rs` 仍负责 GUI 运行标记和崩溃记录。Task17A 的事务记录与其
协同，但不复制 PID 存活判断、崩溃日志格式或窗口恢复逻辑。

## 4. 数据文件

所有文件位于 `%APPDATA%\\RustNT`：

| 文件 | 用途 | 写入方式 |
| --- | --- | --- |
| `shell_snapshot.toml` | 最近一次成功生成的 Shell 快照 | 唯一临时文件写入后原子替换 |
| `shell_recovery.log` | 有界恢复事件日志 | 追加后按总大小裁剪 |
| `shell.session` | 当前启动事务标记 | 创建新文件；正常退出后删除 |

文件格式均带有 `format_version`。未知版本必须返回可读错误并保留原文件，
不能被静默覆盖。

### 4.1 快照结构

快照至少包含：

- `format_version`；
- UTC 采集时间；
- 采集进程 PID；
- 注册表来源和目标值名称；
- 值类型；
- 值是否存在；
- 值内容的 UTF-8 安全长度；
- 内容摘要；
- 成功、缺失或读取失败的结果；
- 失败时的受限错误类别和 Win32 错误码（如可用）。

Task17A 读取当前用户范围的 Winlogon Shell 配置：

- `HKCU\\Software\\Microsoft\\Windows NT\\CurrentVersion\\Winlogon\\Shell`；
- `HKCU\\Software\\Microsoft\\Windows NT\\CurrentVersion\\Winlogon\\Userinit`。

注册表读取通过 Windows API 封装在窄接口中。生产实现不使用外部命令；测试
通过注入式读取器提供固定结果。快照默认不保存完整值，只保存受限长度和
摘要，避免把路径或用户环境信息直接扩散到日志。

## 5. 启动事务状态机

事务状态为：

- `NotStarted`：不存在当前事务；
- `Starting`：已创建 `shell.session`，正在采集和保存快照；
- `Running`：启动流程完成，GUI 正常运行；
- `Completed`：正常退出已经记录并完成清理；
- `RecoveryRequired`：发现上一事务未完成；
- `RecoveryRecorded`：恢复事件已写入本地日志；
- `SnapshotUnavailable`：快照读取或保存失败，但 GUI 仍可启动。

启动流程：

1. 检查 `shell.session` 是否存在且格式有效。
2. 若上次事务未完成，追加一次 `recovery_required` 事件。
3. 创建本次事务标记，记录 PID、启动时间和格式版本。
4. 只读读取两个 Shell 配置值。
5. 尝试原子保存快照；失败时记录 `snapshot_unavailable`，不阻止 GUI。
6. 将事务状态推进到 `Running`。
7. GUI 正常退出时追加 `completed` 事件并删除本次事务标记。
8. 强制终止或崩溃时保留事务标记，由下一次启动识别。

启动阶段的恢复记录失败不得伪装成成功。若无法写入日志或事务标记，错误
必须返回给现有 GUI 启动错误处理；快照单独失败则只降级为可见通知并继续。

## 6. 日志与错误处理

每条事件至少包含：事件时间、PID、状态、事件类型、结果和单行错误摘要。
错误摘要必须移除控制字符并限制长度，不包含完整注册表值内容。

`shell_recovery.log` 使用固定上限。追加导致超限时保留最近的完整事件，
不能截断 UTF-8 字符或留下半条事件。日志文件损坏、版本未知或无法解析时，
应保留原文件并生成新的受限错误结果；不能因为历史日志损坏而删除快照或
阻止 GUI 进入。

所有文件操作使用 Rust 标准库和现有 Windows 原子替换模式。临时文件名必须
包含 PID、时间和进程内计数器，并在成功替换或失败退出时清理。

## 7. 测试策略

### 7.1 快照模型与读取器

- 正常读取 `Shell` 和 `Userinit`；
- 单个值缺失而另一个值正常；
- 注册表访问拒绝；
- 注册表类型不符合预期；
- NUL 或无效 UTF-16 输入的安全处理；
- 内容只保留长度和摘要，不写入完整值；
- 读取器错误包含受限类别和错误码。

### 7.2 文件持久化

- 首次写入创建目标文件；
- 重复写入使用唯一临时文件；
- 原子替换后快照可重新解析；
- 替换失败时保留旧快照；
- 临时文件在成功和失败路径清理；
- 日志裁剪保留最近完整事件且不超过上限；
- 损坏或未知版本文件不会覆盖有效文件。

### 7.3 事务与集成

- 无旧事务时正常进入 `Running`；
- 未完成事务触发一次 `recovery_required`；
- 快照失败仍可进入 `Running` 并记录 `snapshot_unavailable`；
- 正常退出记录 `completed` 并删除当前事务标记；
- 异常终止模拟保留事务标记，下一次启动可恢复识别；
- Task14 运行标记、崩溃恢复和配置读写测试继续通过；
- 不调用外部进程、不执行注册表写入的边界由测试和代码审查确认。

## 8. 验收标准

1. Task17A 只读取当前用户 Shell 配置，不修改 Windows Shell 或注册表。
2. 快照、事务标记和恢复日志只写入 `%APPDATA%\\RustNT`。
3. 发生快照读取或保存错误时，GUI 仍能启动并保留可见错误结果。
4. 异常终止可由下一次启动识别，正常退出可以完成事务清理。
5. 所有持久化文件有版本、大小限制和失败保留策略。
6. 新增逻辑有注入式单元测试，且不依赖真实用户注册表内容。
7. Task14、Task15、Task16 既有行为不变；服务、驱动、内核和权限边界不变。

## 9. 后续边界

Task17B 才能单独讨论手动 Shell 切换。进入 Task17B 前必须重新确认：

- 用户明确启用流程；
- 原配置备份与恢复步骤；
- 独立于 RustNT GUI 的救援路径；
- 启动失败、崩溃和升级失败时的回退策略；
- 不可恢复时如何保证用户仍能进入 Windows 桌面。

Task17A 的完成不代表 RustNT 已替换 Windows Shell，也不代表系统配置已经
发生任何改变。
